Wildcat Hostel website

A mobile-first marketing website for a backpacker hostel on the edge of Yala National Park in Sri Lanka, built so that all the business content lives in one config file and the same components can be reused for the next tourism business.

How the site is put together

  1. 01Config fileEvery business fact: name, contact, booking links
  2. 02Data filesRooms, reviews and other content
  3. 03ComponentsHold no business content, only layout
  4. 04Seven pagesEach ends with WhatsApp, Booking.com and Hostelworld booking routes
  • 7 Pages Home, About, Rooms, House Rules, Gallery, Location and Contact
  • 3 Booking routes WhatsApp, Booking.com and Hostelworld on every page
  • 1 Config file Holds all business content, so a new client means new content, not new components

Problem

The hostel needed its own website that works well on phones and sends guests straight to the booking channels it already uses. I also wanted the build to be reusable, so that a site for another tourism business in Sri Lanka would mean new content rather than new code.

Approach

The site is built with Next.js, React and TypeScript and styled with Tailwind CSS, mobile first. The Location page has live Google Maps directions, and every page ends with the three booking routes so a guest is never more than one tap from booking.

Key decision: keep every business fact out of the components

Components never hold content: the name, contact details and booking links live in one config file and the rest in data files, so forking the project for another client means rewriting those files and leaving the components untouched.

Results

The site has been live on the hostel's own domain since September 2026, hosted on Hostinger.

Limitations and next steps

  • There are no traffic or booking numbers yet, so I cannot say whether the site has changed bookings.
  • The template has one client so far, so reuse is a design goal rather than a proven result.
