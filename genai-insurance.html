GenAI insurance document extraction

An LLM pipeline that reads messy synthetic insurance documents in overlapping chunks, returns schema-checked JSON for each chunk and merges it into one record per document, with a small classifier on top that showed me exactly where a 14-document dataset runs out.

Context
Self-built project to practise GenAI extraction and feature engineering on realistic insurance documents
My part
Sole author
Data
14 synthetic documents: 8 policies, 3 ESG reports, 3 incident reports
Stack
Python, Groq API (LLaMA), pandas, scikit-learn, Jupyter
Status
Complete, on synthetic data only
Links
Code on GitHub

Pipeline

  1. 01ChunkAbout 250 words with a 50-word overlap
  2. 02ExtractLLaMA via Groq fills a strict JSON schema
  3. 03ValidateEach output checked against the schema and allowed values
  4. 04MergeChunk records reduced to one record per document
  5. 05ModelFeatures into logistic regression and a random forest
  • 14 Synthetic documents Policies, ESG and incident reports of about 700 to 1,900 words each
  • 7 Schema fields Entity, region, sector, risk type, time horizon, risk factors and a summary
  • 0.50 Classifier ROC AUC On 5 test documents: chance level, so it tells me nothing about the classifier yet

Problem

Insurance work starts with long, unstructured text: policy wording, ESG reports and incident reports. Before any model can use them, the useful facts, such as who the entity is, which region and sector it is in, what kind of risk it describes and over what time horizon, have to come out as consistent structured fields.

Approach

Each document is split into overlapping chunks of about 250 words so details near a boundary are not lost, and every chunk goes to a LLaMA model through the Groq API with a prompt that asks for one strict JSON object. The outputs are validated against the schema and controlled vocabularies, and then a MapReduce-style step merges the chunk records into one record per document.

After cleaning and light normalisation, the records become features for two classifiers, logistic regression with balanced class weights and a random forest, with the train and test split made before any preprocessing so nothing leaks from the test set.

Key decision: make the model fill a fixed schema

Instead of asking for free-text summaries, the prompt fixes seven fields and limits risk type, region and time horizon to allowed values, which means every chunk comes back in the same shape, validation is a mechanical check rather than a judgement, and the merge step can combine records without guessing what a field means.

Results

The extraction and merge steps produced one record per document for all 14 documents. The classifier results are where the project is most useful as a lesson, because with 9 training documents and 5 test documents both models got identical scores, with a ROC AUC of 0.50, which is chance level.

Limitations and next steps

  • The high-risk label is a proxy based on document type and line of business, because synthetic documents have no loss history, and document category is also one of the features, so the label partly leaks into the inputs.
  • Five test documents cannot support any claim about the classifier. The pipeline needs many more documents, ideally real ones with real outcomes.
  • I did not measure extraction accuracy against hand-labelled fields, which is what I would add first, so that schema validity and field correctness are reported separately.
  • Next steps I would take: retrieval-augmented extraction, SHAP for clearer feature effects, and evaluation on new unseen documents.
